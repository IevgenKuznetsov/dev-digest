# Insights

> Draft — entries are under human review. Last updated: 2026-08-12.

- `2026-08-01` **Recurring Errors & Fixes:** On Windows, `import.meta.url === \`file://${process.argv[1]}\`` never matches (forward slashes vs backslashes, triple vs double slash) — CLI entrypoints silently skip execution with no error. Fix: use `pathToFileURL(resolve(process.argv[1])).href` instead — `server/src/db/migrate.ts:37`, `server/src/db/seed.ts:227`
- `2026-08-01` **What Doesn't Work:** Extending a vendor/shared Zod schema with `.nullable()` (e.g. `RunSummary.extend({ cost_usd: z.number().nullable() })`) makes the field **required** in the object — every existing consumer constructing the base type without it fails typecheck. Use `.nullish()` instead for backward-compatible optional+nullable fields — `server/src/vendor/shared/contracts/run-cost.ts`
- `2026-08-03` **Recurring Errors & Fixes:** Extracting route handler bodies into service classes with explicit return types (e.g. `Promise<PrMetaFindings[]>`) surfaces a cascade of `string` vs Zod literal-union mismatches — Drizzle `select()` infers DB columns as `string` / `string[]`, not `Severity | FindingCategory | FindingKind | TrifectaComponent`. Routes hid this because Fastify inferred the return type loosely. Fix: cast each field (`fr.severity as Severity`) or cast the aggregate (`as PrMetaFindings['findings_preview']`) — `server/src/modules/pulls/service.ts:196-206`
- `2026-08-06` **Recurring Errors & Fixes:** `platform.ts` stores string literals using Unicode curly quotes (U+2018/U+2019) rather than ASCII apostrophes. The Edit tool on Windows replaces them with straight ASCII quotes in the surrounding context, but the new block arrives with curly quotes too — TypeScript rejects them with "invalid character" TS1127 errors. Fix: after any edit to that block, run `node -e` to replace `\u2018`/`\u2019` with `'` in the affected lines — `server/src/vendor/shared/contracts/platform.ts:52-57`
- `2026-08-07` **What Doesn't Work:** Intent service reading plan/spec files via direct `fs.readFile` from user-controlled PR body links is a path traversal vector — regex `[\w\-./]` allows `../` sequences. Fix: use `path.posix.normalize()` + reject paths starting with `..` or absolute, and route through the git adapter (`container.git.readFile`) for DI mockability — `server/src/modules/reviews/intent-service.ts:26-38`
- `2026-08-07` **Codebase Patterns:** New routes in a module must delegate to the module's Service class, not instantiate `ReviewRepository(container.db)` directly. Routes → Service → Repository is the established onion pattern; skipping the service layer breaks DI testability and scatters business logic — `server/src/modules/reviews/routes.ts:158-189`, `server/src/modules/reviews/service.ts`
- `2026-08-12` **Codebase Patterns:** `BlastResult` from `repo-intel/types.ts` uses camelCase internally (`changedSymbols`, `viaSymbol`, `impactedEndpoints`) but the API contract (`blast-api.ts`) uses snake_case (`changed_symbols`, `via_symbol`, `impacted_endpoints`). The mapping happens in `PullsService.getBlastForPr()` — any new consumer must map explicitly or silent `undefined` fields appear in the response — `server/src/modules/pulls/service.ts`, `server/src/modules/repo-intel/types.ts:63-87`
- `2026-08-12` **What Doesn't Work:** `getResolvedCallers` does `INNER JOIN file_rank` — returns 0 rows when `file_rank` is empty (pre-T3 or partial index). But `getFileFacts` has no such join, so `impacted_endpoints` can be non-empty while `callers` is empty. The `tryPersistentBlast` fallback uses `getCachedReferencesTo` (no `file_rank` join) with `rank: 0` and `degraded: true` — `server/src/modules/repo-intel/service.ts:341-360`, `server/src/modules/repo-intel/repository.ts`
