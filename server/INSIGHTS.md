# Insights

- `2026-08-01` **Recurring Errors & Fixes:** On Windows, `import.meta.url === \`file://${process.argv[1]}\`` never matches (forward slashes vs backslashes, triple vs double slash) — CLI entrypoints silently skip execution with no error. Fix: use `pathToFileURL(resolve(process.argv[1])).href` instead — `server/src/db/migrate.ts:37`, `server/src/db/seed.ts:227`
- `2026-08-01` **What Doesn't Work:** Extending a vendor/shared Zod schema with `.nullable()` (e.g. `RunSummary.extend({ cost_usd: z.number().nullable() })`) makes the field **required** in the object — every existing consumer constructing the base type without it fails typecheck. Use `.nullish()` instead for backward-compatible optional+nullable fields — `server/src/vendor/shared/contracts/run-cost.ts`
- `2026-08-03` **Recurring Errors & Fixes:** Extracting route handler bodies into service classes with explicit return types (e.g. `Promise<PrMetaFindings[]>`) surfaces a cascade of `string` vs Zod literal-union mismatches — Drizzle `select()` infers DB columns as `string` / `string[]`, not `Severity | FindingCategory | FindingKind | TrifectaComponent`. Routes hid this because Fastify inferred the return type loosely. Fix: cast each field (`fr.severity as Severity`) or cast the aggregate (`as PrMetaFindings['findings_preview']`) — `server/src/modules/pulls/service.ts:196-206`
- `2026-08-06` **Recurring Errors & Fixes:** `platform.ts` stores string literals using Unicode curly quotes (U+2018/U+2019) rather than ASCII apostrophes. The Edit tool on Windows replaces them with straight ASCII quotes in the surrounding context, but the new block arrives with curly quotes too — TypeScript rejects them with "invalid character" TS1127 errors. Fix: after any edit to that block, run `node -e` to replace `\u2018`/`\u2019` with `'` in the affected lines — `server/src/vendor/shared/contracts/platform.ts:52-57`
- `2026-08-07` **What Doesn't Work:** Intent service reading plan/spec files via direct `fs.readFile` from user-controlled PR body links is a path traversal vector — regex `[\w\-./]` allows `../` sequences. Fix: use `path.posix.normalize()` + reject paths starting with `..` or absolute, and route through the git adapter (`container.git.readFile`) for DI mockability — `server/src/modules/reviews/intent-service.ts:26-38`
- `2026-08-07` **Codebase Patterns:** New routes in a module must delegate to the module's Service class, not instantiate `ReviewRepository(container.db)` directly. Routes → Service → Repository is the established onion pattern; skipping the service layer breaks DI testability and scatters business logic — `server/src/modules/reviews/routes.ts:158-189`, `server/src/modules/reviews/service.ts`
- `2026-08-12` **Codebase Patterns:** `BlastResult` from `repo-intel/types.ts` uses camelCase internally (`changedSymbols`, `viaSymbol`, `impactedEndpoints`) but the API contract (`blast-api.ts`) uses snake_case (`changed_symbols`, `via_symbol`, `impacted_endpoints`). The mapping happens in `PullsService.getBlastForPr()` — any new consumer must map explicitly or silent `undefined` fields appear in the response — `server/src/modules/pulls/service.ts`, `server/src/modules/repo-intel/types.ts:63-87`
- `2026-08-12` **What Doesn't Work:** `getResolvedCallers` does `INNER JOIN file_rank` — returns 0 rows when `file_rank` is empty (pre-T3 or partial index). But `getFileFacts` has no such join, so `impacted_endpoints` can be non-empty while `callers` is empty. The `tryPersistentBlast` fallback uses `getCachedReferencesTo` (no `file_rank` join) with `rank: 0` and `degraded: true` — `server/src/modules/repo-intel/service.ts:341-360`, `server/src/modules/repo-intel/repository.ts`
- `2026-08-15` **Codebase Patterns:** `RunTrace.specs_read` changed from `z.array(z.string())` to `z.array(z.union([z.string(), SpecReadEntry]))`. The union is required because the CI trace-builder (`trace-builder.ts`) still accepts `string[]` callers and existing DB JSONB traces may contain the old format. The client's `TraceBody.tsx` must normalize with `typeof sp === 'string' ? { path: sp, category: 'other', tokens: 0 } : sp` — `server/src/vendor/shared/contracts/trace.ts:88`, `server/src/platform/trace-builder.ts`
- `2026-08-15` **What Works:** Registering `@fastify/multipart` locally inside a child plugin (not globally in `app.ts`) prevents multipart parsing from affecting all other routes — use `await app.register(multipart, { limits: { fileSize: MAX } })` inside the feature plugin — `server/src/modules/project-context/routes.ts`
- `2026-08-15` **What Doesn't Work:** `ReturnType<typeof this.methodName>` in a method return type annotation causes TS2683 ("'this' implicitly has type 'any'") — TypeScript does not allow `this` references in generic type arguments in return positions. Use a named interface (e.g. `ContextDocResult`) instead — `server/src/modules/project-context/service.ts:245`
- `2026-08-15` **Recurring Errors & Fixes:** `resolveAndValidatePath` used `normalClone + '/'` as the path prefix guard — on Windows, `path.resolve()` returns backslash-separated paths so `startsWith(normalClone + '/')` always returns false, silently rejecting ALL paths including valid ones. Fix: import `sep` from `node:path` and use `normalClone + sep` — `server/src/modules/project-context/service.ts:407-416`
- `2026-08-15` **Codebase Patterns:** Drizzle `eq` (and other ORM operators) imported directly in a Service class is an architectural violation — ORM belongs exclusively in the Repository layer. Convert any raw Drizzle query in a service to a named repo method (e.g. `getRepoForWorkspace(workspaceId, repoId)`) and call it via `this.repo`. This also naturally enables workspace ownership checks that a bare `getById` would skip — `server/src/modules/project-context/service.ts`, `server/src/modules/project-context/repository.ts`
- `2026-08-15` **What Doesn't Work:** When a hook types a server response as a flat array (e.g. `SkillContextDoc[]`) but the server actually returns an envelope object (`{ attached: SkillContextDoc[], totalAvailable: number }`), the component receives an object and iterates it as `[]` — silent empty list, no error thrown. TypeScript won't catch this if the hook return type annotation is wrong. Always match the hook return type to the actual API contract and update all consuming components together — `client/src/lib/hooks/project-context.ts:167`, `client/src/app/skills/_components/SkillContextSection/SkillContextSection.tsx:25`
- `2026-08-15` **What Doesn't Work:** Service methods that accept `workspaceId` but discard it with `void workspaceId` protect writes (via repo-level cross-workspace checks) but leave reads as horizontal IDORs — any authenticated user can read another workspace's data by guessing a UUID. Fix: add an ownership check before the query (e.g. `repo.getAgentForWorkspace(workspaceId, agentId)` → throw NotFoundError if null). Writes and reads must both be scoped — `server/src/modules/project-context/service.ts:248,276`
- `2026-08-17` **Recurring Errors & Fixes:** Drizzle `const [row] = await db.select()` + subsequent `if (!row) return null` does NOT narrow `row` to non-undefined for TypeScript — TS still considers it `T | undefined` after the guard. Fix: use `const rows = await ...; const row = rows[0]; if (!row) return null;` — this pattern narrows correctly — `server/src/modules/onboarding/repository.ts`
- `2026-08-17` **What Doesn't Work:** Fastify with a Zod body schema rejects body-less POST requests (no Content-Type header) with 400/422 even when the body is optional per the spec. Fix: define the schema as `z.union([YourSchema, z.undefined(), z.null()]).optional()` so Fastify accepts both a valid body and no body — `server/src/modules/onboarding/routes.ts`
- `2026-08-17` **What Doesn't Work:** `req.raw.setTimeout()` is not available on the mock IncomingMessage created by Fastify `inject()` — calling it unconditionally in a route handler throws in integration tests. Fix: guard with `if (typeof req.raw.setTimeout === 'function')` before calling — `server/src/modules/onboarding/routes.ts:76`
- `2026-08-16` **Recurring Errors & Fixes:** When extracting a `private resolveAndValidatePath(...)` method into a shared module-level import, all `this.resolveAndValidatePath(...)` calls in the class body must be changed to `resolveAndValidatePath(...)` — TypeScript does not flag this as an error (the method was private; the name is now an in-scope import), but it throws `TypeError: this.resolveAndValidatePath is not a function` at runtime — `server/src/modules/project-context/service.ts`, `server/src/platform/paths.ts`
- `2026-08-17` **Codebase Patterns:** `completeStructured` throws `ExternalServiceError` with message containing `'failed schema validation'` when all parse retries are exhausted, vs any other message for network/provider errors. Service layers must inspect `err.message.includes('failed schema validation')` to remap parse exhaustion to HTTP 500 (not 502) per spec — without this check, both failure modes surface as 502 and AC-X1 is violated — `server/src/platform/llm/openai.ts:132`, `server/src/platform/llm/anthropic.ts:147`, `server/src/modules/onboarding/service.ts:161`
- `2026-08-17` **Tool & Library Notes:** Fastify 5 with Zod type provider returns HTTP 422 (not 400) for body schema validation failures — test assertions expecting 400 will fail. The plan-verifier flagged this as a PARTIAL when an integration test asserted `statusCode === 400` but received 422. Always assert 422 for Zod-validated body rejections — `server/src/modules/onboarding/routes.it.test.ts:127`
- `2026-08-17` **Codebase Patterns:** `enrichSmartDiffSummaries` mutates the `SmartDiff` object in-place and returns `Promise<void>` — the caller in `getSmartDiff` must NOT try to reassign its return value. The mutation pattern (vs returning a new value) was chosen to avoid re-building the grouped structure after enrichment — `server/src/modules/pulls/classifier.ts`, `server/src/modules/pulls/service.ts:433`
- `2026-08-17` **Tool & Library Notes:** `LLMProvider.completeStructured` returns `{ data, tokensIn, tokensOut, model, costUsd, raw, attempts }` — NOT OpenAI-style `prompt_tokens`/`completion_tokens`. Any service logging token usage must read `result.tokensIn` and `result.tokensOut` — `server/src/modules/risk-brief/service.ts:251`, `server/src/adapters/mocks.ts`
- `2026-08-17` **What Doesn't Work:** Calling `enrichSmartDiffSummaries` inside `PullsService.getSmartDiff` (a GET handler) blocks for up to 30 s of LLM latency on every first load, disabling the client's Smart Diff button for the entire wait (client `useSmartDiff` has `staleTime: 30_000` so subsequent tab switches use cache, but cold loads and post-expiry fetches still block). Fix: move enrichment to a fire-and-forget block at the end of `ReviewRunExecutor.executeRuns`, persist results to `pr_files.pseudocode_summary`, and read from DB in `getSmartDiff` — `server/src/modules/pulls/service.ts:392`, `server/src/modules/reviews/run-executor.ts`
- `2026-08-17` **What Doesn't Work:** Risk brief LLM call receives only file paths (no patch content) — LLM always outputs `line: 1` for all `file_refs` and `review_focus` items because it has no diff evidence. Fix: use `getPrFiles()` (returns `{path, patch}[]`) instead of `getPrFilePaths()`, budget-cap total patch chars (30 000), and add a system-prompt rule that `line` must be omitted when not derivable from a hunk header — `server/src/modules/risk-brief/service.ts:122`, `server/src/modules/risk-brief/repository.ts:140`, `server/src/prompts/risk-brief.system.md`
- `2026-08-20` **Recurring Errors & Fixes:** pgvector queries silently return zero rows when the column's dimensionality does not match the embedding model's output dimension. No error is thrown — the query just has no matches. After upgrading embedding models (e.g., OpenAI text-embedding-3-large outputs 3072 dimensions, not 1536), the existing `embeddings` column (created with the old dimension) returns empty results for similarity searches. Fix: after model change, recompute all stored embeddings AND recreate the column with correct dimensions — `ALTER TABLE <table> ALTER COLUMN embedding TYPE vector(<new-dim>)` — then backfill. Verify model dims match column dims before deploying — `server/src/adapters/embedder.ts`, `server/src/db/schema/*.ts`
- `2026-08-21` **Codebase Patterns:** The eval precision formula changed (v2): old formula was `findingsMatchingMustFind / totalActualFindings` and could return `null` when `totalActualFindings === 0` with must_find expectations. New formula is `(matchedMustFind + satisfiedMustNotFlag) / (totalMustFind + totalMustNotFlag + unmatchedFindings)` and returns `0` (not `null`) when denominator > 0. Any test asserting `expect(m.precision).toBeNull()` from the old formula is now wrong — use `toBe(0)` — `server/src/modules/evals/scoring.ts:159`
- `2026-08-25` **Tool & Library Notes:** Drizzle-kit `db:generate` on a branch can produce a migration with the same numeric prefix (e.g. `0017_mean_pestilence.sql`) as an unmerged migration from another branch — both `.sql` files coexist in `migrations/` but only the journaled one runs. The orphan file is silently ignored by the migrator but pollutes the directory and confuses `ls`. Check `meta/_journal.json` to confirm which file is actually registered — `server/src/db/migrations/meta/_journal.json`
- `2026-08-25` **Tool & Library Notes:** `yaml` package `stringify()` does NOT accept a `blockSeq` option — passing it causes TS2769 "No overload matches this call". The only valid top-level options are from `DocumentOptions & SchemaOptions & ParseOptions & CreateNodeOptions & ToStringOptions`. Use `lineWidth: 0` to disable line wrapping; block style is the default for most values — `server/src/modules/ci/workflow.ts`
- `2026-08-25` **Recurring Errors & Fixes:** Vitest `vi.mock()` factory functions are hoisted before all variable declarations in the test file — any factory referencing an outer `const` (e.g. `mockReturnValue(MOCK_RUNNER)`) throws `ReferenceError: Cannot access '...' before initialization`. Always use literals inside `vi.mock()` factories; assign the variable after the mock call if needed — `server/src/modules/ci/service.test.ts`
- `2026-08-25` **What Doesn't Work:** `ci_runs` has no `duration_ms` column and no FK to `agent_runs` (which does have `duration_ms`). The ingest flow inserts both rows but they are not linked — `duration_s` in `GET /ci/runs` response is always `null`. To populate it, either add a `duration_ms` column to `ci_runs` (set during upsert) or add an `agent_run_id` FK for join access — `server/src/db/schema/ci.ts`, `server/src/modules/ci/service.ts:280`
