- `2026-08-02` **Recurring Errors & Fixes:** `Severity` from `@devdigest/ui` (tokens.ts) is a 4-member union including `"INFO"`, while `Severity` from `@devdigest/shared` (findings.ts) is only 3 members (`CRITICAL|WARNING|SUGGESTION`). Using the UI type to index a map keyed by the shared type causes TS7053 — import from `@devdigest/shared` when working with finding data — `client/src/vendor/ui/primitives/tokens.ts:3`, `client/src/vendor/shared/contracts/findings.ts:11`
- `2026-08-02` **What Doesn't Work:** Absolutely-positioned floating panels (tooltips, popovers) inside the PR list table are clipped because `tableCard` uses `overflow: hidden` for its border-radius. Fix: render via `ReactDOM.createPortal(…, document.body)` and compute position from `getBoundingClientRect()` — `client/src/app/repos/[repoId]/pulls/styles.ts:90`, `client/src/vendor/ui/kit/Tooltip.tsx`
- `2026-08-04` **Recurring Errors & Fixes:** React's style diffing warns "conflicting property" when mixing CSS shorthand (`border: "none"`) with longhand (`borderBottomStyle`, `borderBottomColor`) on the same element. Fix: replace the shorthand with individual longhands (`borderTop: "none"`, `borderLeft: "none"`, `borderRight: "none"`) — common in tab bar active-state styling — `client/src/app/skills/_components/SkillsListView/styles.ts:tab()`
- `2026-08-06` **Codebase Patterns:** `client/src/vendor/shared/` is a physical copy of `server/src/vendor/shared/`, NOT a symlink. Adding a new contract file to the server copy does NOT update the client — typecheck passes server-side but fails client-side with "has no exported member". Fix: copy the new `.ts` file to `client/src/vendor/shared/contracts/` AND add its barrel export to `client/src/vendor/shared/index.ts` — `client/src/vendor/shared/index.ts`, `server/src/vendor/shared/index.ts`
- `2026-08-07` **What Doesn't Work:** TanStack Query caches 404 errors as failed queries that never auto-refetch. If a feature populates data asynchronously (e.g. intent classified during a review run), the initial 404 sticks and the UI stays empty. Fix: explicitly invalidate the query key when the async operation completes — `client/src/app/repos/[repoId]/pulls/[number]/page.tsx:159`
- `2026-08-07` **Codebase Patterns:** `FileCard` is intentionally NOT exported from the `@/components/diff-viewer` barrel (`index.ts` exports only `DiffViewer` + `DiffCommentApi`). Components that need to render individual file cards must import directly from the internal subpath: `import { FileCard } from "@/components/diff-viewer/FileCard"` — `client/src/components/diff-viewer/index.ts:3`
- `2026-08-07` **What Doesn't Work:** Icon names used in `ROLE_ICONS` (or any `IconName`-typed field) must exist in the `Icon` registry (`client/src/vendor/ui/icons.tsx`). Lucide names like `Code2`, `Package`, `Boxes` are NOT registered — passing them causes a silent void render with no TS error (the `Icon[name]` lookup returns `undefined`). Safe alternatives for code/config/bundle roles: `Code`, `Settings`, `File` — `client/src/vendor/ui/icons.tsx:86-165`
- `2026-08-07` **What Doesn't Work:** `Badge` from `@devdigest/ui` does NOT accept an `onClick` prop — passing it causes TS2322 at compile time. If a badge needs to be clickable, wrap it in a `<div role="button">` or `<button>` instead — `client/src/vendor/ui/kit/Badge.tsx`
- `2026-08-07` **Codebase Patterns:** Severity CSS variables use short names from `@devdigest/ui` tokens: `--crit`/`--crit-bg` (red), `--warn`/`--warn-bg` (yellow), `--sugg`/`--sugg-bg` (blue). Do NOT use `--sev-warning` or similar — those don't exist. The canonical map is `SEV` in `client/src/vendor/ui/primitives/tokens.ts` — `client/src/components/diff-viewer/styles.ts:4-8`
- `2026-08-07` **Codebase Patterns:** Smart Diff enriches line highlights with severity data by joining `SmartDiffFile.finding_lines` (line numbers only) with full `FindingRecord[]` from `usePrReviews()`. The `findingsMap: Map<number, LineFinding>` is built in `SmartDiffViewer` and passed to `FileCard` → `CodeLine`. When `findingsMap` is absent, `FileCard` falls back to the plain `findingLines` array with WARNING-level highlighting — `client/src/components/diff-viewer/FileCard/FileCard.tsx`, `client/src/app/.../SmartDiffViewer/SmartDiffViewer.tsx`
- `2026-08-07` **Codebase Patterns:** Cross-tab finding navigation (Diff → Findings) uses a 3-level cascade: `page.tsx` sets `tab="findings"` + `highlightFinding={findingId, nonce}` → `FindingsTab` resolves `findingId` → `review_id` via `runs[]` and sets `target` → `ReviewRunAccordion` opens + scrolls → `FindingsPanel` uses `requestAnimationFrame` before `scrollIntoView` on `[data-finding-id]` to ensure the accordion content is rendered. Without `requestAnimationFrame`, the scroll target doesn't exist yet — `client/src/app/.../FindingsPanel/FindingsPanel.tsx`, `client/src/app/.../FindingsTab/FindingsTab.tsx`
- `2026-08-07` **What Doesn't Work:** Multi-line finding ranges (`start_line..end_line`) in the diff highlight ALL lines, but the badge ("Blocker"/"Warning") only renders on `start_line`. If `start_line` falls outside visible diff hunks (collapsed context), the badge silently disappears. Fix: `FileCard` tracks shown `findingId`s via a `Set` during line iteration and promotes the first visible `isRangeOnly` line to show the badge — `client/src/components/diff-viewer/FileCard/FileCard.tsx`
- `2026-08-07` **Codebase Patterns:** File-header finding badges (per-severity pills in `FileCard`) are intentionally non-clickable — they only `stopPropagation` to avoid toggling file collapse. Line-level annotations in `CodeLine` remain clickable (navigate to Findings tab). This split is deliberate: header badges show ALL findings per severity in their tooltip, so there's no single target to navigate to — `client/src/components/diff-viewer/FileCard/FileCard.tsx:107-152`, `client/src/components/diff-viewer/CodeLine/CodeLine.tsx`
- `2026-08-12` **Recurring Errors & Fixes:** `String.prototype.split(" ")[0]` with destructuring (`const [method] = ep.split(" ")`) yields `string | undefined` under `noUncheckedIndexedAccess`. Fix: use index access with nullish coalescing `const method = ep.split(" ")[0] ?? ""` — client typecheck fails otherwise — `client/src/app/repos/[repoId]/pulls/[number]/_components/OverviewTab/_components/BlastCard/BlastCard.tsx`
- `2026-08-12` **Codebase Patterns:** BlastCard GraphView per-symbol groups connect symbol→callers→endpoints via `factsByFile`. When `factsByFile` has no matching caller file keys (degraded/partial index), endpoints are invisible even though `impacted_endpoints` is populated. The SymbolGraph component shows a "DEGRADED — need indexing" placeholder node in this case — `client/src/app/repos/[repoId]/pulls/[number]/_components/OverviewTab/_components/BlastCard/BlastCard.tsx`
- `2026-08-15` **Recurring Errors & Fixes:** Relative imports in deep `_components/` folders fail Vitest's Vite import resolver even when `tsc --noEmit` passes — because tsc resolves from the project root while Vite resolves from the file's directory. Counting levels wrong (6 vs 5 for a file at `src/app/agents/[id]/_components/X/X.tsx`) breaks the test but not typecheck. Fix: always use `@/` alias (`@/lib/hooks/...`) in components nested 4+ directories deep — `client/src/app/agents/[id]/_components/AgentContextTab/AgentContextTab.tsx`
- `2026-08-15` **Codebase Patterns:** `apiFetch` in `api.ts` calls `res.json()` — it fails for endpoints that return raw `text/plain` (e.g. file content routes). Add and use `apiText(path)` for those routes; it calls `res.text()` instead. `useContextDocContent` hit this because the `/content` endpoint returns raw markdown, not JSON — `client/src/lib/api.ts:109`, `client/src/lib/hooks/project-context.ts:64`
- `2026-08-16` **Architectural Constraint:** `SETTINGS_SECTIONS` from `@devdigest/ui` (`vendor/ui/nav.ts`) cannot be edited (vendor). To add a new settings nav item, define a local `LOCAL_SECTIONS = [...SETTINGS_SECTIONS, { key, label }]` array in `SettingsView.tsx` and render that instead — `client/src/app/settings/[section]/_components/SettingsView/SettingsView.tsx`
- `2026-08-16` **Codebase Patterns:** `Settings` (from `@devdigest/shared`) uses Zod `.passthrough()`, so arbitrary extra keys (e.g. `context_scan_patterns`) can be stored and retrieved without schema changes. However TypeScript types them as `unknown` — access via `(settings as Record<string, unknown>)?.['my_key'] as MyType | undefined`. Mutate via `updateSettings.mutate({ my_key: value } as any)` — `client/src/vendor/shared/contracts/platform.ts:99`
